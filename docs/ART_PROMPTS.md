# 『ほしふる灯台』画像生成プロンプト集（Gemini 向け最終版）

`docs/PLAN.md` §4 の下書きを、Google Gemini の画像生成にそのまま貼り付けられる形に整えた正本です。
各プロンプトは **1 セルで完結** しており、置換用のプレースホルダーはありません。表のプロンプトをコピーして Gemini に貼れば生成できます。

- 文章は日本語、プロンプトは英語（生成が安定するため）
- 歩行スプライトとタイルセットは CC0 素材を使う方針（PLAN §9）のため、CH-xxC と TL-xx は **任意／参照用**
- 生成した画像は `art/raw/` に置くだけでよく、切り抜き・縮小・登録は開発側（`scripts/` のスクリプト）で行う（§2.3）

---

## 1. Gemini 向けの使い方

### 1.1 使うモデルと設定

| 項目             | 推奨                                                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| アプリ           | Gemini アプリ（gemini.google.com）の「画像を作成」ツール。API や AI Studio でも同じプロンプトが使える（要実機確認・§7.2）                                                                    |
| モデル           | 既定の Nano Banana 2（Gemini 3.1 Flash Image）で十分。キービジュアル（KV-01/02）だけ Nano Banana Pro（Gemini 3 Pro Image）を試す価値あり（要実機確認・§7.2）                                 |
| 比率             | オプションバーの **アスペクト比セレクタ** で選び、さらに **プロンプト冒頭にも言葉で書く**（例: `Widescreen 16:9 image.`）。両方書けばセレクタが無い環境でも効く（要実機確認・§7.2）          |
| 解像度           | 既定（1K）で足りる。ゲーム側で縦 360px まで縮小するため、2K/4K は KV-04（OG 画像）以外不要                                                                                                   |
| ネガティブ指定   | 専用欄は無い。除外したいものは **文中に肯定形か "no ..." で書く**（本書のプロンプトには既に含めてある）                                                                                      |
| 透過             | 透過 PNG は出力できない前提。切り抜く素材は **単色の純緑 (#00FF00)**（緑系の被写体は **純マゼンタ (#FF00FF)**）の背景で生成し、後処理でクロマキー抜きする                                    |
| 参照画像         | 同一キャラを複数枚に登場させるときは、採用済みの画像を添付して「この人物と同一」と指示する（最大 14 枚まで添付できるが、本プロジェクトでは 1〜3 枚で足りる）                                 |
| 文字             | 画像内の文字は不要。全プロンプトに `No text, no letters ...` を入れている。ロゴは別途コードで描く                                                                                            |
| ウォーターマーク | 無料／AI Pro プランでは右下に小さな Gemini マークが入る（AI Ultra では無し）。切り抜き素材は背景側に落ちるので問題なし。全面絵（KV/BG）は後処理で右下 2〜3% をトリムする（要実機確認・§7.2） |

### 1.2 作業手順（素材 1 点あたり）

1. **顔アイコンを最初に作る**: CH-01B1 / CH-02B1 / CH-03B1（ルカ・ミオ・ゴローの無表情）を先に生成・採用する。以後、同じキャラが出る画像（立ち絵、表情差分、KV-01/02、BO-04）では **採用した顔アイコンを参照画像として添付** する。
2. 新しいチャットを開き、該当する表のプロンプトを **全文そのまま** 貼る。参照画像が必要な行はプロンプトに `Use the attached image ...` と書いてあるので、画像を添付してから送信する。
3. 比率は言葉で書いてあるが、アプリのアスペクト比セレクタでも同じ比率を選ぶ。
4. **1 画像 1 被写体** が原則。「a single image, not a collage or grid」と書いてあるのは、Gemini が複数案を 1 枚にまとめがちなため。
5. 結果を §6 の採用基準でチェックする。NG のときは **同じチャット内で追加指示** を出す方が、作り直しより速い。
   - 文字が入った → `Remove every letter, word and symbol from the image. Keep everything else exactly the same.`
   - 余計な物がある → `Remove the <object>. Keep the character and the background exactly the same.`
   - 背景が単色でない → `Replace the entire background with a solid, flat, pure green (#00FF00). Change nothing else.`
   - 向きや構図だけ直す → `Keep the same character, same colors and same style, but <変更内容>.`
6. 1 素材につき **最大 4 回** まで試し、それでも決まらなければ飛ばして進む（後でまとめて再挑戦）。細部のこだわりより全素材を揃えることを優先する。
7. 保存は **ダウンロードボタンから元サイズの PNG**（JPEG/WebP しか選べない場合はそれで可。スクリーンショットや SNS 経由の再保存は圧縮が入るので避ける）。
8. §2.1 の命名規約でリネームし、`art/raw/` に入れる。§5 のチェックリストに状態を書く。

### 1.3 プロンプトの書き方（自作・修正するとき）

- Gemini は **キーワード列挙より文章** のほうが安定する。「何を・どこで・どんな構図で・どんな画風で」を文で書く。
- 「無いもの」を書くより **「ある状態」を書く**（例: `no cars` より `an empty street`）。ただし文字・透かし・コラージュの排除だけは `No text ...` の形で明示する。
- 編集指示では「何を変えるか」と同時に **「何を変えないか」を明示** する（`Keep ... exactly the same`）。
- 画像に文字を入れたい場合は引用符で囲んで指定できるが、本プロジェクトでは画像内文字は使わない。

## 2. 命名規約と置き場所

### 2.1 ファイル名

```
<ID>_<slug>.png        例: EN-01_lost-star-slime.png
                            CH-01B2_luka-face-smiling.png
```

- ID はハイフンを含めて表の通り。slug は小文字英数字とハイフンのみ
- 置き場所は `art/raw/`（Git 管理外）。候補を複数残す場合は末尾に `-v2`, `-v3` を付け、採用版だけ無印にする
- 加工後の正式ファイルは実装担当が `public/assets/images/<category>/` に出力し、`src/assets/manifest.ts` に登録する

### 2.3 開発側の後処理（自動）

`art/raw/` に置かれた PNG に対して、以下を `scripts/` のスクリプトで一括実行します。ユーザー側での切り抜きやリサイズは不要です。

| 工程               | 内容                                                                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| クロマキー除去     | ImageMagick で `#00FF00`（または `#FF00FF`）を許容差 10〜15% で透過化 → 余白をトリム → 縮小時に色が滲まないよう緑成分の残りを除去 |
| 縮小               | **最近傍補間（nearest neighbour）** で目標サイズへ。ドットの輪郭を保つため、縮小後に 1px 外形線の再整形は行わない                 |
| 透過の付与         | UI-01 の窓中央は不透明で生成し、後処理で中央領域にアルファ 85% を設定                                                             |
| 9-slice 切り出し   | UI-01 を 96×96 に縮小後、32px 単位の 3×3 に分割（Phaser の `NineSlice` で使用）                                                   |
| スプライトシート化 | 顔アイコンの表情差分、属性・状態アイコン、アイテムアイコン、タッチボタンは `montage` で 1 枚に結合し、フレーム座標を JSON 化      |
| 派生サイズ         | 顔アイコン 96×96 → 戦闘用 48×48 を自動生成。favicon 64×64 → 32×32 / 16×16                                                         |
| 圧縮               | `pngquant`／`oxipng`（利用可能なもの）で可逆〜準可逆圧縮。合計 15MB 以下（PLAN §6）                                               |
| マニフェスト登録   | `src/assets/manifest.ts` にキー・パス・フレームサイズを追加。プレースホルダー描画から差し替わる                                   |
| ウォーターマーク   | 全面絵（KV・BG）は右下 3% をトリムしてから 16:9 にリサイズ。切り抜き素材は背景側に落ちるため追加処理なし                          |

**STYLE（ドット絵系: キャラ・敵・UI・アイコン）**

```
16-bit pixel art in the style of a SNES-era Japanese RPG, clean pixel outlines, a limited palette of about 32 colors, flat cel shading with two-tone highlights, crisp hard edges with no anti-aliasing and no gradients, warm nostalgic coastal-fantasy mood, light coming from the upper left.
```

```
A detailed pixel-art illustration in the style of 16-bit JRPG key art, painterly dithering, a rich but limited palette, soft bloom from starlight, cinematic composition, light coming from the upper left.
```

**CHROMA（切り抜く素材の背景指定。緑系の被写体はマゼンタ版を使う）**

```
The background is a solid, flat, pure green (#00FF00) with nothing else in the frame; the subject is centered with clear margin on all sides and does not touch the edges.
```

```
The background is a solid, flat, pure magenta (#FF00FF) with nothing else in the frame; the subject is centered with clear margin on all sides and does not touch the edges.
```

**EXCL（除外文。全プロンプトの末尾）**

```
A single image, not a collage or grid. No text, no letters, no captions, no watermark, no signature, no border.
```

**REF（参照画像を使うときの前置き）**

```
Use the attached image as the exact same character: keep the same face, hair, outfit and colors.
```

## 6. 採用基準

### 6.1 全素材共通

1. **文字・記号・透かしが無い**（右下の Gemini マークは除く）。ルーン・紋章・看板・地図など、文字に見える模様も不可
2. **1 枚に 1 被写体**。コラージュ・分割・バリエーション並列になっていない
3. **背景が単色** で、被写体と背景の境界がはっきりしている（切り抜く素材のみ）。被写体が枠に接していない
4. **光源が左上** で統一されている（影が右下に落ちる）
5. **パレットが抑えられている**（ドット絵系は 32 色程度、アイコンは 8〜12 色）。グラデーションや写実的な質感が無い
6. **目標サイズに縮小して判別できる**。迷ったらブラウザで縮小表示して確認する
7. 手・指・脚の本数、左右対称性など **破綻が無い**（ドット絵系は多少の崩れは縮小で消えるので許容）

## 7. 調査メモ（Gemini 画像生成の仕様確認・2026-10-05 時点）

本書の運用ルールの根拠です。本作業環境では Google の公式ドメイン（ai.google.dev、support.google.com、docs.cloud.google.com、discuss.ai.google.dev、workspaceupdates.googleblog.com）への直接取得がネットワーク制限で失敗したため、**直接確認できたもの** と **検索結果の要約のみで確認したもの** を分けて記載します。後者は Gemini を実際に開いて最初の数枚で確認してください。

### 7.1 直接確認できたこと

出典: Google Cloud ブログ「The ultimate prompting guide for Nano Banana」 https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-nano-banana

- 画像生成モデルの現行名: **Nano Banana 2 = Gemini 3.1 Flash Image**、**Nano Banana Pro = Gemini 3 Pro Image**。解像度は Nano Banana 2 が 512px / 1K / 2K / 4K、Pro が 1K / 2K / 4K
- アスペクト比: 両モデルで 1:1, 3:2, 2:3, 3:4, 4:3, 4:5, 5:4, 9:16, 16:9, 21:9（Nano Banana 2 は 1:4, 4:1, 1:8, 8:1 も）。**幅×高さのピクセル指定はできない**ため、本書は比率で指定し、最終サイズは後処理で揃える
- 参照画像: 1 プロンプトに **最大 14 枚** を添付でき、「参照画像 + 関係の指示 + 新しい状況」の形で書くのが推奨
- プロンプトの書き方: 「キーワード列挙でなく **文章で場面を描写** する」「**肯定形で書く**（no cars ではなく empty street）」「編集時は **変えない部分を明示** する」「会話で反復して詰める」
- 文字を入れる場合は引用符で囲む（本プロジェクトでは画像内文字を使わないため、逆に「No text ...」を全プロンプトに付けている）
- ネガティブプロンプト欄の記載は無い。除外は文中で行う

### 7.2 検索結果の要約のみで確認したこと（要実機確認）

- Gemini アプリの画像生成は「画像を作成」ツールから行い、**モデル選択（Nano Banana 2 / Nano Banana Pro）とアスペクト比の選択肢** がオプションバーにある（2026 年 2 月の Nano Banana 2 アプリ投入時に「アスペクト比コントロール」「キャラクター保持」が追加されたとされる）
  - https://workspaceupdates.googleblog.com/2026/02/introducing-nano-banana-2-in-gemini-app.html
  - https://helpx.adobe.com/firefly/web/work-with-images/generate-images/generate-images-using-gemini.html（Adobe Firefly 経由の UI 説明。アプリ本体の UI と差がある可能性あり）
- **透過 PNG（アルファ付き）は出力できない**。公式フォーラムに「Unable to create Transparent PNGs」のスレッドがあり、単色背景で生成して後処理で抜くのが一般的な回避策。本書はこれを前提に **純緑 #00FF00（緑系の被写体はマゼンタ #FF00FF）** を指定している
  - https://discuss.ai.google.dev/t/unable-to-create-transparent-pngs/92868
- API 側の設定名は `imageConfig.aspectRatio`（および `imageSize`）。幅・高さの直接指定は無い
  - https://discuss.ai.google.dev/t/how-to-set-image-width-or-height-in-gemini-image-2-5-flash-api/133728
  - https://ai.google.dev/gemini-api/docs/image-generation（公式リファレンス。本環境からは取得不可）
- **ウォーターマーク**: 生成画像にはすべて不可視の SynthID が入る。無料と Google AI Pro では右下に可視の Gemini マークが付き、AI Ultra では付かないとされる。設定で可視マークをオフにできるようになったという情報もあるが、本環境では確認できなかった。本書は「可視マークが付く」前提で後処理（切り抜き素材は背景側に落ちる、全面絵は右下をトリム）を組んである
  - https://www.techradar.com/ai-platforms-assistants/gemini/you-can-now-ask-the-gemini-app-if-an-image-was-made-by-ai-thanks-to-googles-synthid-tool
- **利用上限**: 無料プランは 1 日あたり約 100 枚（Nano Banana）、Nano Banana Pro は数枚程度、AI Pro / Ultra で上限が増えるとされる。数値はプラン改定で変わるため、生成を始める日に Gemini アプリ側の表示で確認する
  - https://ai.zenken.co.jp/en/post/gemini-image-guide/
- 以前、アプリが比率指定を無視して正方形しか返さない不具合が報告されたことがある。比率を **セレクタと文中の両方** で指定しているのはこのため。それでも正方形になる場合は、目的の比率の無地画像（例: 1920×1080 の黒）を参照画像として添付し「この画像と同じ比率で」と指示する回避策がある（未検証）
  - https://www.androidauthority.com/google-gemini-square-images-3603128

### 7.3 未確認・不明点（運用でカバー）

- Gemini アプリのダウンロード形式（PNG か JPEG か）と、保存時の解像度（1K のままか）は実機で確認する。JPEG しか出ない場合もクロマキー抜きは許容差を広げて対応できる
- 無料プランで 1 日 100 枚前後なら、本書の必須 118 点（試行 180〜350 回）は **2〜4 日** に分けるのが現実的。AI Pro 以上なら 1〜2 日
- ドット絵風の出力は「ドット絵に見える絵」であり、グリッドに揃った真のピクセルアートではない。最近傍補間で縮小すると多くは馴染むが、気になる素材は Aseprite 等で手直しする（PLAN §4.1 対策 A）
