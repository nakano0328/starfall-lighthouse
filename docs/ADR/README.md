# ADR（Architecture Decision Records）

技術的な決定とその理由を、後から振り返れるように短い文書で残します。

## 運用ルール

- ファイル名は `NNNN-短い英語スラッグ.md`。番号は 4 桁ゼロ埋めの連番（`0001-tech-stack.md`, `0002-...`）
- 1 ファイル 1 決定。決定を覆すときは新しい ADR を書き、旧 ADR の冒頭に「状態: 置き換え済み（→ 000X）」と追記する。旧ファイルは消さない
- 依存パッケージの追加・削除、ディレクトリ構成の変更、データ形式（セーブ・マップ・会話 JSON）の変更は ADR の対象
- 小さな判断は既存 ADR の「影響・代替案」への追記で済ませてよい
- 本文は日本語。コード・パッケージ名・コマンドは英語

## テンプレート

```markdown
# NNNN. タイトル

- 日付: YYYY-MM-DD
- 状態: 採用 | 提案 | 置き換え済み（→ NNNN）

## 状況

何を決める必要があったか。制約や前提。

## 決定

何を選んだか。バージョンや設定値は具体的に。

## 理由

なぜそれを選んだか。

## 影響・代替案

この決定で楽になること・縛られること。検討して採用しなかった選択肢と、見送った理由。
```
