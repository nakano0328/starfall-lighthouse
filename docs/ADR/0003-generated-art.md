# ADR-0003: 素材はリポジトリ内のスクリプトでコードから生成する

- 日付: 2026-10-18
- 状態: 採用

## 状況

`docs/PLAN.md` Phase 6 は「ユーザーが Gemini で生成した画像を後処理して差し替える」「歩行スプライトとタイルは CC0 素材」を前提にしていた。しかし開発セッションからは CC0 配布サイト（Kenney・OpenGameArt）へ到達できず、生成画像の到着を待つと Phase 6 が止まる。一方で、ユーザーからは「足りない素材は作りながら進めてよい」と指示があった。

タイルセットは 26 枚のマップが同じ `PLACEHOLDER_TILES` のインデックス配置（`src/data/tiles.ts`、8 列）を前提にしており、エリアごとに見た目だけ変えたい。

## 決定

- 画像素材は `scripts/art/` の TypeScript が **決定的に**描画し、`npm run art` で `public/assets/images/` に PNG を書き出す。生成物の PNG もコミットする（ビルドに生成工程を挟まない）
- PNG の書き出しは `scripts/art/png.ts` の最小エンコーダ（Node 標準の `zlib` のみ）で行い、画像ライブラリを devDependencies に追加しない。描画プリミティブは `scripts/art/pixmap.ts`
- タイルセットは `scripts/art/tiles.ts` がエリア別パレット（village / interior / forest / mine / ruins / lighthouse）で同じインデックス配置の 6 枚を出力する。マップは `MapMeta.tilesets[0]` にエリアのキーを書き、`WorldScene` は埋め込みタイルセット名（`ts_placeholder`）はそのままに **テクスチャだけ**を差し替える。PNG の読み込みに失敗した場合は従来どおり `BootScene` がプレースホルダーを生成する
- 装飾専用タイル（岩・柵・花・木・レール・レバー・石碑）は背景透過、地面としても使われるタイル（ランタン・机・鉱石など）はエリアの床を背景に不透明で描く（§9.3 の legend の使われ方に合わせる）
- 生成素材は自作扱い（MIT）。`docs/CREDITS.md` には「画像（生成素材）」節に一文で記し、スタッフロールの表には載せない（コード生成の素材は表に不要というルールどおり）
- 本番用に差し替えたい素材は、同じキー・同じサイズの PNG を置けばスクリプト生成分を上書きできる（`manifest.ts` の `src` は変えない）

## 理由

- 待ちなしで Phase 6 を進められ、差分は全部テキスト（描画コード）でレビューできる
- 出力が決定的なので、Vitest でサイズ・透過規則・再現性を検証できる
- ライセンス管理が不要（自作）。後から AI 生成画像や CC0 素材へ置き換える道も塞がない

## 影響・代替案

- 品質は手描きのドット絵や生成画像に及ばない。見た目の改善は `scripts/art/` の描画コードを直す作業になる
- 代替案「CC0 素材パック」はネットワーク制約で入手できず見送り。「Python/PIL で生成」はツールチェーンが増えるため、既存の `scripts/run-ts.mjs`（Vite のモジュールランナーでパスエイリアスが効く）に乗る TypeScript を選んだ
- 代替案「実行時に Phaser の Graphics で描き続ける（プレースホルダーの延長）」は、ドット単位の表現と PNG 差し替えの両立が難しいため見送り
