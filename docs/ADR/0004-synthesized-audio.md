# ADR-0004: BGM・SE は音声ファイルを持たず、実行時にソフトシンセで合成する

- 日付: 2026-10-18
- 状態: 採用

## 状況

`docs/PLAN.md` Phase 6 は BGM 9〜11 曲と SE 約 26 種を CC0 素材または音楽生成 AI で用意する想定だった。ADR-0003 と同じく開発セッションから配布サイトへ到達できず、音声ファイルの到着を待つと「音入り」のマイルストーン M5 が止まる。また、音声ファイルを置くと 1 曲あたり数百 KB〜数 MB になり、GitHub Pages の配布物と PR の差分が大きくなる。

`docs/GAME_DESIGN.md` §15 のキー一覧（`bgm_*` 11、`se_*` 26）と、設定画面の音量 0〜10（§11）はすでに決まっていて、シーン側はキーで鳴らせればよい。

## 決定

- 音声ファイルは置かない。曲と効果音は **データ**（`src/data/audio/bgm.ts`・`se.ts`）として譜面とレシピで記述し、**純 TypeScript のソフトシンセ**（`src/core/audio/`）が実行時に PCM へ描画する
  - `notes.ts`: 譜面記法。トークンは `c4` `g#3q` `r` のように「音名＋オクターブ＋長さ」。長さは `w` 全／`h` 2 分／`q` 4 分／無印 8 分／`s` 16 分、`.` で付点、`~` でタイ、`|` は小節の見た目のための区切りで無視する
  - `synth.ts`: `renderTrack(track, sampleRate)` がチャンネル（square / pulse / triangle / sawtooth / sine / noise、ADSR、ビブラート、移調）を合成してモノラルの `Float32Array` を返す。ループ曲は小節末のリリースの尾をループ先頭に折り返し、`tanh` のソフトクリップで仕上げる。`renderSe(recipe, sampleRate)` は周波数スイープを重ねた短音
- 再生は `src/audio/AudioPlayer.ts` が Web Audio API を直接扱う。Phaser のサウンドは `audio: { noAudio: true }` で無効化する
  - 最初のキー入力／タッチで `AudioContext` を作成・再開する（自動再生制限）。解除前に要求された BGM は保留し、解除直後に鳴らす
  - レンダリングは初回再生時に行いサンプルレートごとにキャッシュする。解除直後に主要な SE を先に描画しておく（`warmUp`）
  - BGM は `AudioBufferSourceNode` の `loop` で回し、曲の切り替えは既定 400 ms のクロスフェード。同じキーの再要求は何もしない（マップ遷移で途切れさせない、§15.1）。戦闘後は `restart` で頭から再開する
  - 音量は設定の 0〜10 を `(v / 10)^2` のゲインに写して BGM・SE 別の `GainNode` に掛ける
- 全 11 曲は 4 拍子でチャンネルの拍数が等しいこと、全 26 種の SE が可聴であることを Vitest で検証する（`tests/unit/audio-*.test.ts`）。曲の差し替えは譜面データの編集、音色の改善は `synth.ts` の作業になる
- 生成音は自作扱い（MIT）。`docs/CREDITS.md` には「BGM・SE」節に一文で記し、スタッフロールの表には載せない

## 理由

- 待ちなしで M5 を終えられ、差分はすべてテキスト（譜面とレシピ）でレビューできる
- 配布物に音声ファイルが増えない（11 曲 + 26 種でコード数十 KB）。ライセンス管理も不要
- 合成が純 TypeScript なので、Web Audio の無い Vitest でも長さ・ループ・音量を検証できる

## 影響・代替案

- 音質はチップチューン相当で、生楽器や生成 AI の曲には及ばない。将来本物の音源に替えるときは `AudioPlayer` の `playBgm(key)` / `playSe(key)` の内側だけを差し替えればよく、シーン側のキー呼び出しは変えない
- 初回再生時に曲 1 本あたり数十 ms の合成が走る。キャッシュするので 2 回目以降は無い
- 代替案「Phaser の Sound Manager に AudioBuffer を渡す」は、Phaser 3 の Web Audio 実装が `AudioBuffer` の直接登録をキャッシュ経由でしか受け付けず、クロスフェードや解除の制御が回りくどいため、直接 Web Audio を使う方を選んだ
- 代替案「ビルド時に WAV/OGG へ書き出して配布する」はファイルサイズが増え、ADR-0003 の「生成物をコミットする」方針とも合わない（音は描画より生成物が大きい）ため見送り
